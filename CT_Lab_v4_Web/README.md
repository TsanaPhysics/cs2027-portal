# CT-Lab v4.0 — Computational Thinking Interactive Simulator

เว็บสื่อการเรียนรู้แนวคิดเชิงคำนวณแบบโต้ตอบภาษาไทย ใช้งานบนคอมพิวเตอร์และโทรศัพท์มือถือ

## วิธีเริ่มใช้งาน

**ทางเลือกที่ง่ายที่สุด:** เปิดไฟล์ `CT_Lab_Interactive_v4_Algorithms_Flowcharts.html` ผ่าน Google Chrome, Microsoft Edge หรือ Safari ได้ทันที โดยไม่มีการติดตั้งโปรแกรม ไม่มีบัญชีผู้ใช้ และไม่จำเป็นต้องเชื่อมต่ออินเทอร์เน็ต

**สำหรับนักพัฒนา:** เปิดไฟล์ `index.html` ในโฟลเดอร์ `CT_Lab_v4_Web` โดยให้ไฟล์ `.css` และ `.js` ทั้งหมดอยู่ในโฟลเดอร์เดียวกัน สามารถนำไปเผยแพร่ผ่าน Static Hosting เช่น GitHub Pages, Netlify หรือเซิร์ฟเวอร์ของสถานศึกษา

## การใช้โมดูล 08

1. **ระบบรดน้ำ:** เปลี่ยนตัวเลื่อน H แล้วดูว่า `H < 0.1` ให้เปิดน้ำหรือปิดน้ำ กด Step หรือ Auto เพื่อทดลองการวนซ้ำ; การเพิ่ม/ลดความชื้นในแต่ละรอบเป็นกฎจำลองที่สร้างขึ้นเพื่อการสอน ไม่ใช่โมเดลทางเกษตรหรือเซ็นเซอร์จริง
2. **หาค่า Min:** กรอกเลขคั่นจุลภาค แล้วกดตรวจทีละค่าเพื่อดู Min เปลี่ยนแปลง
3. **ตรรกะ:** เปิด–ปิด A/B แล้วอ่านตารางความจริง AND/OR/NOT พร้อมตอบคำถามฝึกคิด
4. **นับสินค้า:** ระบุ M และรายการราคาสินค้า กด Step เพื่อดูว่าราคา `x ≤ M` ส่งผลให้ `count` เพิ่มเมื่อใด

ทำกิจกรรมถูกต้องอย่างน้อย 2 ห้องทดลอง เพื่อบันทึกความสำเร็จโมดูล 08

## การใช้โมดูล 09

1. เลือกด่าน: แปรงฟัน ใส่เสื้อเชิ้ต เดินทางมาโรงเรียน ทอดไข่ หรือล้างจาน
2. คลิกบล็อกจากคลังด้านขวาเพื่อเพิ่มท้ายลำดับ หรือลากบล็อกไปวางตามตำแหน่ง (เบราว์เซอร์ที่รองรับ Drag & Drop)
3. บนมือถือใช้ปุ่ม `↑`, `↓`, `×` เพื่อปรับลำดับหรือนำบล็อกออก
4. กด **ตรวจผังงาน** เพื่อดูจำนวนตำแหน่งที่ตรงกับลำดับตัวอย่าง กด **คำใบ้** หากต้องการแนวทาง และ **ดูการทำงาน** เพื่อเดินตามเส้นทางตัวอย่าง

ด่านที่มีเงื่อนไขแสดงป้ายทางเลือก “ใช่/ไม่ใช่” และการจำลองเส้นทางหนึ่งเป็นตัวอย่าง มิได้แสดงสาขาแบบลากเส้นเต็มรูปแบบทุกกรณี ผังงานที่สมเหตุสมผลอาจมีมากกว่าหนึ่งรูปแบบ โดยเฉพาะกรณีมีทางเลือกและการวนซ้ำ การตรวจอัตโนมัติใช้ลำดับตัวอย่างที่กำหนดไว้ ไม่ใช่เครื่องพิสูจน์ความถูกต้องของผังงานทุกแบบ

## ระบบฐานข้อมูลต้นแบบและ AI ตรวจงาน-รายงานอัตโนมัติ (v4.0 Database & AI Upgrade)

ระบบรองรับการทำงานเป็น **ต้นแบบระบบฐานข้อมูลการเรียนการสอน** พร้อม **เอนจิน AI ตรวจงาน ให้คะแนน และสร้างรายงานอัตโนมัติ** ดังนี้:

### 1. สถาปัตยกรรมฐานข้อมูล Dual-Engine (`database.sql`, `api/config.php`)
- **Multi-Environment PDO**: เชื่อมต่อ MySQL อัตโนมัติทั้งบนเซิร์ฟเวอร์มหาวิทยาลัย (`rbru.ac.th`) และ XAMPP ในเครื่อง (Unix Socket / `127.0.0.1`) พร้อม **SQLite Fallback อัตโนมัติ** (`data/ctlab_local.sqlite`) เมื่อไม่ได้เปิด MySQL
- **ตารางมาตรฐานในฐานข้อมูล**:
  - `ctlab_students` — ทะเบียนรายชื่อนักศึกษาและกลุ่มเรียน (มีรายชื่อเริ่มต้น 26 รายการรวม `TEACHER01`)
  - `ctlab_submissions` — ประวัติการส่งงาน พร้อมคอลัมน์ผลตรวจ AI (`ai_score`, `ai_rubric_json`, `ai_feedback`, `ai_model`, `ai_graded_at`) และคะแนน/ความเห็นผู้สอน
  - `ctlab_ai_reports` — คลังบันทึกรายงานวิเคราะห์ผลการเรียนระดับชั้นเรียนที่ AI สร้างขึ้น
  - `vw_ctlab_student_summary` — View สรุปผลคะแนนและสถานะการส่งงานรายบุคคล

### 2. ระบบ AI ตรวจงานและให้คะแนนตามเกณฑ์ Rubric (`api/ai_grader.php`, `api/submit.php`, `api/challenge.php`)
เมื่อนักศึกษากดส่งงาน AI จะประเมินคะแนนรวม (0–100) แยกตาม 3 องค์ประกอบอัตโนมัติ:
1. **Simulation Mastery (40 คะแนน)**: ตรวจสถานะการผ่านกิจกรรม จำนวนรอบทดลอง และหลักฐานโค้ด/ค่าที่กรอกใน `snapshot`
2. **Block Sequencing / Parsons Problem (35 คะแนน)**: ตรวจการจัดเรียงบล็อกขั้นตอนวิธีด้วย LCS และคัดกรองบล็อกตัวลวง (Distractor) รายโมดูล
3. **Subjective Reasoning (25 คะแนน)**: วิเคราะห์คำตอบอัตนัยและบันทึกผู้เรียนด้วยคีย์เวิร์ดมโนทัศน์แนวคิดเชิงคำนวณและตรรกะเหตุผล (รองรับการเสริมด้วย Gemini API หรือ Local Ollama เมื่อกำหนดค่าในหน้าผู้สอน)
- **โมดูล 10 (`api/challenge.php`)**: ตรวจคำตอบฝั่งเซิร์ฟเวอร์และสร้างคำแนะนำรายหัวข้อโดยไม่เปิดเผยเฉลย A/B/C/D แก่นักศึกษา

### 3. ระบบผู้สอนและรายงานวิเคราะห์อัตโนมัติ (`teacher.html`, `api/admin.php`)
- **AI Batch Grading & Re-grade**: ปุ่มสั่งให้ AI ตรวจและอัปเดตคะแนนทุกงานที่ส่ง หรือวิเคราะห์ซ้ำรายบุคคลพร้อม Rubric Breakdown
- **แท็บ "รายงานวิเคราะห์ด้วย AI (AI Auto-Report)"**:
  - สร้างบทสรุปผู้บริหารและข้อเสนอแนะเชิงวิชาการอัตโนมัติ (Executive Summary)
  - วิเคราะห์คะแนนเฉลี่ยแยกตาม **4 เสาหลักแนวคิดเชิงคำนวณ** (Decomposition, Pattern Recognition, Abstraction, Algorithm Design)
  - วิเคราะห์ความยากและจุดติดขัดรายโมดูล (Module Bottleneck & Distractor Trap)
  - คัดกรองนักศึกษากลุ่มเสี่ยง (`< 50%` หรือยังไม่ส่งงาน) และกลุ่มดีเด่น (`>= 80%`)
  - รองรับการจำลองข้อมูลส่งงาน (`Demo Seed`), บันทึกลง `ctlab_ai_reports`, Export CSV/Gradebook, และสั่งพิมพ์/บันทึก PDF

## ข้อมูลความก้าวหน้าและขอบเขตระบบ

- หน้าห้องทดลองเก็บความคืบหน้าใน `localStorage` แบบ Offline-first และส่งขึ้นฐานข้อมูลผ่าน `api/submit.php` / `api/challenge.php` เมื่อเปิดผ่านเซิร์ฟเวอร์เว็บ
